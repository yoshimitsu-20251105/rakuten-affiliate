# 専門用語集(GLOSSARY)

非エンジニア・非SEO専門家でも理解できることを優先した用語集。新しい専門用語がプロジェクトに登場したら、このファイルの末尾に同じ形式で追記する(過去の行は書き換えない)。

各用語は次の5項目で記録する:

- **Term** — 英語表記
- **日本語** — 日本語での呼び方
- **かんたんな意味** — 専門知識がなくても分かる説明
- **今回のプロジェクトでなぜ重要か** — この楽天アフィリエイトプロジェクトにおける意味
- **具体例** — 実際にこのプロジェクトで起きたこと・使っている場所

---

### SEO
- 日本語: 検索エンジン最適化
- かんたんな意味: Googleなどの検索結果で、自分のページがなるべく上の方に表示されるように工夫すること
- 今回のプロジェクトでなぜ重要か: 広告費をかけずに人を集める(=無料の集客経路)ための土台
- 具体例: ページのtitle/見出し/内部リンクを整えることで、検索結果に表示されやすくしている

### SERP
- 日本語: 検索結果画面
- かんたんな意味: Googleで検索した時に表示される一覧ページそのもの(Search Engine Results Page)
- 今回のプロジェクトでなぜ重要か: 自分のページが「その検索結果の中で何位に出るか」「どんなサイトと競合しているか」を把握しないと、勝てるテーマか判断できない
- 具体例: `strategy/competitors.json` に「グレインフリー ドッグフード」のSERP上位サイトを記録している

### CTR
- 日本語: クリック率
- かんたんな意味: 画面に表示された回数のうち、実際にクリックされた割合
- 今回のプロジェクトでなぜ重要か: 検索結果に表示されても(impression)、クリックされなければ意味がない。タイトルや見出しの良し悪しを測る指標
- 具体例: Search Consoleで「表示回数1件・クリック0件」ならCTRは0%

### CVR
- 日本語: コンバージョン率(成約率)
- かんたんな意味: サイトに来た人のうち、実際に買ってくれた(成果につながった)割合
- 今回のプロジェクトでなぜ重要か: アクセスが増えても、CVRが低ければ収益は増えない。アクセス数と切り分けて考える必要がある指標
- 具体例: ページ閲覧9件・affiliate_clickイベント0件なら、CVR以前にクリックすら発生していない状態

### EPC
- 日本語: クリック単価収益(Earnings Per Click)
- かんたんな意味: CTAボタンが1回クリックされるごとに、平均してどれだけの収益が生まれるか
- 今回のプロジェクトでなぜ重要か: 複数のテーマ・ASPを比較するときの「稼ぐ力」の共通ものさしになる
- 具体例: `strategy/monetization-sources.json` の `epc` フィールド(現状は未検証のためnull)

### CPA
- 日本語: 顧客獲得単価
- かんたんな意味: 1件の成果(購入・申込等)を得るためにかかったコスト
- 今回のプロジェクトでなぜ重要か: 現状は広告費をかけていないため直接関係は薄いが、将来SNS広告等を検討する際の判断基準になる
- 具体例: 現時点では本プロジェクトに該当データなし(UNKNOWN)

### LTV
- 日本語: 顧客生涯価値(Life Time Value)
- かんたんな意味: 1人の顧客が長期的にもたらしてくれる利益の合計
- 今回のプロジェクトでなぜ重要か: 単発購入のVOLUME型か、継続課金のRECURRING/SUBSCRIPTION型かで、狙うべきテーマの優先度が変わる
- 具体例: `strategy/opportunities.json` の `revenueEngines` に `RECURRING`/`SUBSCRIPTION` という分類がある

### KPI
- 日本語: 重要業績評価指標
- かんたんな意味: 「結局何を見て良し悪しを判断するか」という数値の指標
- 今回のプロジェクトでなぜ重要か: 記事数やコード量ではなく、Revenue/EPC/Conversion Rate等のKPIで成果を測るという方針そのものの土台(CLAUDE.md参照)
- 具体例: `strategy/experiments.json` の `metrics`/`successThreshold`/`killThreshold`

### GA4
- 日本語: Googleアナリティクス4
- かんたんな意味: サイトに来た人が何ページ見たか、どのボタンを押したか等を計測する無料ツール
- 今回のプロジェクトでなぜ重要か: affiliate_clickイベント(楽天CTAのクリック)を実際に計測している唯一の手段
- 具体例: `keyword-research/publication-preview-template.js` のGA4計測タグ・affiliate_clickイベント送信スクリプト

### GSC
- 日本語: Googleサーチコンソール(Search Console)
- かんたんな意味: 自分のサイトがGoogle検索でどれだけ表示・クリックされているかを確認できる無料ツール
- 今回のプロジェクトでなぜ重要か: 「そもそもGoogleに見つけてもらえているか」を確認する唯一の手段。indexされていなければSEOの努力自体が意味をなさない
- 具体例: `keyword-research/cli/search-trial-report.js`(安全ゲート付きのGSC/GA4読み取り専用レポートCLI)

### API
- 日本語: 外部システムとの接続窓口
- かんたんな意味: 自分のプログラムから、楽天やGoogle等の外部サービスのデータを取得・操作するための決まった手順
- 今回のプロジェクトでなぜ重要か: 楽天の商品データ取得、Google Keyword Plannerのデータ取込、GA4/GSCの計測取得は全てAPI経由
- 具体例: 楽天`IchibaItem/Search`API、Google Search Console API等

### CTA
- 日本語: 行動喚起ボタン(Call To Action)
- かんたんな意味: 「見る」「購入する」等、ユーザーに次の行動を促すボタンやリンク
- 今回のプロジェクトでなぜ重要か: このボタンのクリックが収益化の入口(affiliate_clickイベント)になる
- 具体例: 各比較ページの「楽天市場で在庫・価格を確認してください」ボタン

### canonical
- 日本語: 正規URL
- かんたんな意味: 内容が似ているページが複数あっても「本来はこのURLが本物です」とGoogleに伝えるための指定
- 今回のプロジェクトでなぜ重要か: 重複コンテンツとして評価が分散するのを防ぐ
- 具体例: `docs/rankings/senior-cat-food.html` の `<link rel="canonical" href="...">`

### noindex
- 日本語: 検索結果に出さない指定
- かんたんな意味: 「このページは検索結果に表示しないでください」とGoogleに伝えるタグ
- 今回のプロジェクトでなぜ重要か: 下書き段階のページが誤って検索に出てしまうのを防ぐ安全装置
- 具体例: `publication-preview-template.js` は `isDraft:true` の間、常にnoindexを出力する

### sitemap
- 日本語: サイトマップ
- かんたんな意味: サイト内の全ページのURL一覧をGoogleに渡すためのファイル
- 今回のプロジェクトでなぜ重要か: Googleがページを見つけやすくなる(ただし本プロジェクトでは取得失敗の問題が継続観測中)
- 具体例: `docs/sitemap.xml`(`generate-site.js` が自動生成)

### IndexNow
- 日本語: IndexNow(即時インデックス通知の仕組み)
- かんたんな意味: ページを公開・更新したタイミングで検索エンジンに即座に知らせるプロトコル
- 今回のプロジェクトでなぜ重要か: sitemap取得失敗の問題を踏まえ、今後検討しうる代替の通知手段(現状未導入、UNKNOWN)
- 具体例: 本プロジェクトでは未導入

### ASP
- 日本語: アフィリエイトサービスプロバイダー
- かんたんな意味: 広告主とアフィリエイター(紹介する側)を仲介する会社
- 今回のプロジェクトでなぜ重要か: 楽天以外の収益源(Amazon, A8, ValueCommerce等)を検討する際の選択肢
- 具体例: `strategy/monetization-sources.json` に登録(現状レート等は全てnull、未検証)

### Affiliate
- 日本語: アフィリエイト(成果報酬型広告)
- かんたんな意味: 自分のサイト経由で商品が売れた時に、売上の一部を報酬として受け取る仕組み
- 今回のプロジェクトでなぜ重要か: 本プロジェクトの収益源そのもの
- 具体例: 楽天アフィリエイトのリンク経由で商品が購入された場合の成果報酬

### Conversion
- 日本語: コンバージョン(成果・成約)
- かんたんな意味: サイト訪問者が「購入」「申込」等、目的の行動を完了すること
- 今回のプロジェクトでなぜ重要か: 最終的な収益はConversionの発生数と単価で決まる
- 具体例: 楽天での商品購入が成立した時点

### Impression
- 日本語: 表示回数
- かんたんな意味: 検索結果に自分のページが表示された回数(クリックされたかは問わない)
- 今回のプロジェクトでなぜ重要か: ファネルの一番上流。これが0なら、その先(クリック・成果)は発生しようがない
- 具体例: 2026-09-30時点でsenior-dog-pork.htmlがimpressions=1を記録(Search Console実測)

### Organic Search
- 日本語: 自然検索(オーガニック検索)
- かんたんな意味: 広告ではなく、検索結果に自然に表示されてサイトに来る経路
- 今回のプロジェクトでなぜ重要か: 本プロジェクトの集客は広告費を使わないオーガニック検索が前提
- 具体例: `strategy/experiments.json` の `trafficSource: "organic_search"`

### PR / Pull Request
- 日本語: プルリクエスト
- かんたんな意味: 「このコード変更をmaster(本番)に取り込んでよいか確認してください」という提案のかたまり
- 今回のプロジェクトでなぜ重要か: master直接pushを禁止し、必ずPR経由+人間の承認を挟むことで、事故を防ぐ運用になっている
- 具体例: PR #17(新規3ページ)、PR #18(本基盤)

### Branch
- 日本語: ブランチ(枝分かれ)
- かんたんな意味: masterに影響を与えずに、別の作業スペースでコードを変更できる仕組み
- 今回のプロジェクトでなぜ重要か: 複数の作業(新規ページ追加・基盤整備等)を安全に並行して進められる
- 具体例: `feature/search-trial-3-new-pages`、`feature/affiliate-agent-operating-system`

### Merge
- 日本語: マージ(統合)
- かんたんな意味: ブランチでの変更を、master等の本流に取り込むこと
- 今回のプロジェクトでなぜ重要か: マージ=本番反映のタイミングであり、必ず人間の承認を経てから行う
- 具体例: PR #12(犬・猫2ページの検索公開試験)は人間承認後にマージされ本番公開された

### Rebase
- 日本語: リベース
- かんたんな意味: 自分のブランチの土台を、最新のmasterに付け替える操作
- 今回のプロジェクトでなぜ重要か: masterが日次パイプラインで毎日更新されるため、作業ブランチが古くなりやすい。最新状態を踏まえて作業するために使うことがある
- 具体例: 本PR(#18)は作業開始時にorigin/masterの最新コミットから新規ブランチを作成した

### Schema
- 日本語: スキーマ(データの型定義)
- かんたんな意味: 「このデータはこういう項目を必ず持ち、こういう型・値でなければならない」という決まりごと
- 今回のプロジェクトでなぜ重要か: strategy/配下のJSONが壊れたり、項目が抜けたりするのを防ぐ
- 具体例: `strategy/schemas/opportunities.schema.json`

### JSON
- 日本語: JSON(データ形式の一種)
- かんたんな意味: `{ "key": "value" }` のような形で、プログラムが読み書きしやすいようにデータを記録する形式
- 今回のプロジェクトでなぜ重要か: strategy/配下の全データ(機会・実験・決定等)はJSONで管理している
- 具体例: `strategy/experiments.json`

### A/B Test
- 日本語: A/Bテスト
- かんたんな意味: 2つ以上のパターンを同時に試して、どちらが成果が良いか比較する手法
- 今回のプロジェクトでなぜ重要か: 将来、title/H1や内部リンク構造の改善を検証する際に使う可能性がある手法(現状未実施)
- 具体例: 現時点では本プロジェクトに該当データなし(UNKNOWN)
